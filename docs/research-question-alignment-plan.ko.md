# Research-question alignment 검색 개선 계획

작성일: 2026-09-09

## 목적과 이번 작업 범위

연구 질문에 직접 답할 수 있는 논문을 상위에 배치한다. 주제가 비슷하다는 사실, 연구 질문에 답한다는 사실, 연구 가설을 지지한다는 사실을 구분한다. 가설과 반대되는 결과도 같은 질문을 다루면 높은 정합성을 가질 수 있다.

최초 작업은 설계 문서와 가상 사례 적용까지였으며, 후속 작업으로 실제 후보 수집과 수동 평가표 준비를 완료했다. 애플리케이션 코드, 검색 API, 기존 점수와 UI는 변경하지 않았다. 아래 점수·가중치·후보 수는 검증 전 가설이며 확정된 성능 기준이 아니다. 사람 정답 판정과 모델 평가는 아직 실행하지 않았다.

## 현재 구현과 변경 접점

| 단계 | 현재 파일·함수 | 향후 역할 |
|---|---|---|
| 질문 입력·실행 | `apps/web/features/review/hooks/useValidationWorkspace.ts`의 `searchTopic()` | 원문 질문 보존, 검색 실행과 질문 버전 연결 |
| 질문 조건 생성 | `services/api/app/domain/gap_structuring.py`의 `infer_initial_conditions()` | 제한적 단어 규칙에서 구조화된 질문 표현으로 확장 |
| 검색 조율 | `services/api/app/services/search_service.py`의 `run_openalex_search()` | 후보 검색 → 정합성 평가 → 순위 산출 연결 |
| 후보 검색 | `services/api/app/adapters/academic_sources/openalex.py`의 `search()` | 외부 후보와 원본 점수·순위 보존 |
| 근거 분류 | `services/api/app/domain/evidence_classifier.py`의 `classify_gap_evidence()` | 기존 겹침·역할 분류와 별도로 정합성 평가 추가 |
| 검색 결과 정렬 | `services/api/app/repositories/in_memory.py`의 `list_search_results()` | 검색 실행별 최종 순위 조회 |
| 화면 목록 | `EvidenceService.list_gap_evidence()` → `EvidenceList()` | 선택한 검색 실행의 최종 순위와 표시 순서 일치 |

현재 자체 embedding, BM25, dense, hybrid, reranker는 없다. OpenAlex의 반환 순서를 저장한다. evidence 목록은 gap별 삽입 순서이므로 검색 결과 rank만 바꾸면 화면 정렬 개선이 전달되지 않는다. 같은 gap을 여러 번 검색하는 경우도 검색 실행별 결과를 분리해야 한다.

## 질문 구조화 스키마

질문 원문을 보존하고 각 필드에 `value`, `requirement`, `source_span`, `origin`을 둔다.

- `requirement`: `CORE`(직접 답변에 필요한 조건), `PREFERENCE`(선호), `UNSPECIFIED`(미지정).
- `source_span`: 원문에서 해당 해석을 뒷받침하는 정확한 부분 문자열. 명시되지 않은 값을 만들지 않는다.
- `origin`: `EXPLICIT` 또는 `USER_CONFIRMED`. 해석 제안은 별도 `clarification_notes`에 기록하고 확정 필드에 넣지 않는다.
- `UNSPECIFIED` 필드는 `value: null`이며 점수 분모에서 제외한다.
- 구조화 결과는 원문과 함께 버전 관리한다. 연구자가 조건을 수정하면 새 질문 버전으로 평가한다.

| 필드 | 의미 | 판정 시 주의점 |
|---|---|---|
| `population` | 연구 대상·참여자 | 학생·실무자 등 명시된 구분 보존 |
| `intervention_or_phenomenon` | 개입, 기술, 노출, 관찰 현상 | 특정 도구를 질문에 없이 가정하지 않음 |
| `comparator` | 비교 대상·조건 | ‘영향’이라는 단어만으로 무사용 대조군을 확정하지 않음 |
| `outcome` | 설명·측정하려는 결과 | 다양성, 품질, 속도를 서로 대체하지 않음 |
| `context` | 업무·환경·지역 등 | 대상의 직업만으로 실제 현장 연구를 가정하지 않음 |
| `method` | 질문에 명시된 연구 방법 | 방법 미지정이면 질적 연구 등을 일괄 감점하지 않음 |
| `timeframe` | 기간·추적 시점 | 기간 언급이 없으면 장기 연구를 요구하지 않음 |
| `relation` | 무엇과 무엇의 어떤 관계를 묻는지 | 같은 단어의 나열과 실제 관계 분석을 구분 |

추가 최상위 필드: `question_id`, `question_version`, `original_text`, `schema_version`, `clarification_notes`.

예시 질문: “생성형 AI가 UX 디자이너의 아이디어 다양성에 미치는 영향”

| 필드 | 구조화 값 | 필수성 | 원문 근거 |
|---|---|---|---|
| population | UX 디자이너 | CORE | UX 디자이너 |
| intervention_or_phenomenon | 생성형 AI | CORE | 생성형 AI |
| outcome | 아이디어 다양성 | CORE | 아이디어 다양성 |
| relation | 생성형 AI가 아이디어 다양성에 미치는 영향 | CORE | 생성형 AI가 UX 디자이너의 아이디어 다양성에 미치는 영향 |
| comparator / context / method / timeframe | null | UNSPECIFIED | 없음 |

‘영향’은 질문의 관계 방향을 보존한다. 관찰 연구라는 이유만으로 제외하거나 인과 효과가 입증됐다고 해석하지 않는다. 인과 추론의 타당성과 연구 품질은 정합성 점수와 별도 평가 대상이다.

## 질문–논문 정합성 평가표

평가 입력은 질문 구조와 논문 제목·초록이다. 원문 전문을 읽지 않았으면 전문을 확인한 것처럼 판정하지 않는다. 영문 초록과 한국어 질문은 개념 단위로 비교하고, 근거 구절은 원문 언어로 보존한다.

| 판정 | 코드 | 기준 | 점수 기여값 |
|---|---|---|---|
| 일치 | MATCH | 해당 조건을 직접 다루는 근거가 있음 | 1 |
| 부분 일치 | PARTIAL | 상위·인접 개념 또는 대상 일부를 다룸 | 0.5 |
| 불일치 | MISMATCH | 다른 대상·변수 등을 다룬다는 명시적 근거가 있음 | 0 |
| 정보 부족 | UNKNOWN | 제목·초록만으로 판단 불가 | 0, 별도 집계 |

각 판정은 `field`, `label`, `evidence_quote`, `evidence_source`, `reason`을 저장한다. `UNKNOWN`에는 근거 구절을 억지로 만들지 않고 부족한 정보를 설명한다. 근거 인용은 실제 제목·초록의 부분 문자열인지 검증한다. 같은 표현이 등장한다는 것만으로 MATCH를 부여하지 않는다.

`relation`의 MATCH는 논문이 해당 개입과 결과 사이의 관계를 실제 분석했을 때 부여한다. 배경 설명에만 두 개념이 나오는 경우 직접 정합성이 확인된 것으로 취급하지 않는다. 효과 증가·감소·무효라는 결과 방향은 정합성 감점 사유가 아니다.

초기 가중치 제안:

| 필드 | 기본 가중치 |
|---|---:|
| population | 0.15 |
| intervention_or_phenomenon | 0.20 |
| outcome | 0.25 |
| relation | 0.25 |
| comparator | 0.05 |
| context | 0.05 |
| method | 0.025 |
| timeframe | 0.025 |

`PREFERENCE` 가중치는 기본값의 0.5배, `CORE`는 기본값 그대로 사용한다. 활성 필드 집합 A는 UNSPECIFIED를 제외한 집합이다.

```text
alignment_score = 100 × Σ(w_i × contribution_i) / Σ(w_i), i ∈ A
evidence_coverage = Σ(w_i × known_i) / Σ(w_i), i ∈ A
known_i = 0 if UNKNOWN else 1
```

이 점수는 확인된 정합성의 양이며 확률이나 논문 품질 점수가 아니다. UNKNOWN과 MISMATCH는 숫자 기여가 같지만 의미가 다르므로 `core_mismatch_fields`, `unknown_fields`, `evidence_coverage`를 반드시 함께 기록한다. 모든 필드가 미지정이면 점수는 null로 두고 외부 순위를 유지한다.

평가셋에서 검증할 초기 정렬안:

1. 활성 CORE가 모두 MATCH인 후보를 우선 배치한다.
2. 나머지 중 CORE에 MISMATCH가 없는 후보를 배치한다. PARTIAL·UNKNOWN을 포함할 수 있다.
3. CORE에 명시적 MISMATCH가 있는 후보를 배치한다. 제거하지 않는다.
4. 각 그룹 안에서 alignment_score 내림차순, evidence_coverage 내림차순, 원본 순위 오름차순으로 정렬한다.

UNKNOWN이 많은 후보가 명시적 불일치 후보보다 앞서는 것이 적절한지는 별도 오류 분석 대상으로 삼는다. 평가 불가·모델 호출 실패는 UNKNOWN과 구분해 `evaluation_status: FAILED`로 기록한다. 초기 통합에서는 일부라도 평가 실패하면 해당 실행 전체에 외부 순위를 유지하고 fallback 이유를 저장하는 보수적 방식을 사용한다.

## 가상 사례 적용

아래 후보는 평가 규칙 설명을 위해 만든 가상 초록 요약이다. 실재 논문이나 실제 검색 결과가 아니며 검색 품질 개선의 증거로 사용하지 않는다. 외부 순위도 가정이다.

| 후보 | 가상 초록 요약 | 가정한 외부 순위 |
|---|---|---:|
| A | UX 디자이너의 생성형 AI 사용에 따라 아이디어 다양성이 감소했다고 보고 | 4 |
| B | UX 디자이너의 생성형 AI 사용이 작업 완료 시간에 미치는 영향을 분석. 아이디어 다양성은 측정하지 않았다고 명시 | 1 |
| C | 일반 대학생의 생성형 AI 사용과 아이디어 다양성 관계를 분석 | 2 |
| D | UX 디자이너의 생성형 AI 활용을 조사. 초록에는 아이디어 다양성 분석 여부가 제시되지 않음 | 3 |

예시 질문의 활성 가중치 합은 0.85다. 아래 계산은 위 가상 요약에만 근거한다.

| 후보 | 대상 | 개입 | 결과 | 관계 | 점수 | 근거 충족률 | 새 순위 |
|---|---|---|---|---|---:|---:|---:|
| A | MATCH | MATCH | MATCH | MATCH | 100.0 | 100% | 1 |
| D | MATCH | MATCH | UNKNOWN | UNKNOWN | 41.2 | 41.2% | 2 |
| C | MISMATCH | MATCH | MATCH | MATCH | 82.4 | 100% | 3 |
| B | MATCH | MATCH | MISMATCH | MISMATCH | 41.2 | 100% | 4 |

A는 효과가 감소하는 결과여도 질문을 직접 다루므로 최상위다. C는 총점은 높지만 CORE 대상이 달라 후순위 그룹에 놓인다. D는 확인이 더 필요한 후보이며 정합성이 확정된 논문으로 표시하면 안 된다. D와 C의 순서는 대상 조건을 엄격히 보는 초기 정책의 결과다. 사람이 C를 더 유용하다고 평가하면 그룹 우선 정책과 CORE 지정 방식을 재검토한다.

## 실제 평가셋과 실험

### 데이터 구성

- 질문 5~10개를 선정한다. 한국어·영어, 효과·경험·메커니즘 질문, 넓은 질문·구체적 질문을 포함한다.
- 각 질문에 현재 API가 지원하는 최대 50개 후보를 한 번 가져와 응답과 검색 시점을 고정한다. 실제 수집은 후속 작업이다.
- 현재 기본 동작인 상위 10개도 별도 기록한다. 동일한 50개 후보의 외부 상위 10개와 재정렬 상위 10개를 비교하면 reranking 효과를 분리할 수 있다.
- 외부 검색 점수와 순위를 숨긴 상태에서 사람이 논문별 항목 판정과 전체 관련성 등급을 매긴다.
- 사람 전체 등급: 3=질문에 직접 답함, 2=중요한 부분에 답함, 1=배경·인접 근거, 0=관련 없음. 위 수식으로 정답 등급을 자동 생성하지 않는다. 정보 부족은 강제로 0을 주지 않고 별도 표시한다.
- 알려진 직접 관련 논문이 있으면 별도 참조 목록으로 둔다. 후보에 없더라도 reranking 실험 후보에 몰래 추가하지 않는다.
- 질문 단위로 조정용·검증용을 분리한다. 같은 질문의 논문을 양쪽에 나눠 넣지 않는다. 가능하면 일부 표본을 두 사람이 독립 평가하고 불일치를 기록한다.

저장할 평가 레코드: `question_id`, `question_version`, `paper_id`, `search_run_id`, 제목·초록 스냅샷, 원본 순위·점수, 사람 항목별 판정·근거, 사람 전체 등급, 판정자, 정합성 결과, 최종 순위, schema·rubric·model·prompt 버전.

### 비교와 완료 판단

| 지표 | 확인할 내용 |
|---|---|
| nDCG@10 | 사람이 매긴 0~3 등급 기준으로 상위 순서가 개선되는가 |
| 직접 관련 Precision@5 | 상위 5개 중 사람 등급 3의 비율 |
| CORE 불일치@5 | 상위에 질문의 핵심 조건을 벗어난 논문이 얼마나 남는가 |
| UNKNOWN 비율·근거 충족률 | 정보 부족을 낮은 관련성과 혼동하거나 숨기지 않는가 |
| 알려진 관련 논문 후보 포함률 | 참조 논문이 후보 50개에 들어오는가. 전체 문헌 recall로 해석하지 않음 |
| 근거 인용 유효율 | 인용이 실제 제목·초록에 존재하는가 |
| 실행 시간·비용·실패율 | 사용자 흐름에 적용 가능한가 |

정보 부족 논문이 상위에 있으면 추가 판정 대상으로 표시한다. 끝내 판단할 수 없는 항목이 있으면 평가 가능한 범위와 미판정 수를 보고하고, 이를 임의로 0등급 처리한 단일 수치로 결론 내리지 않는다.

검증용 질문에서 외부 순위 대비 nDCG@10과 Precision@5의 질문별·평균 변화를 함께 보고한다. 평균이 좋아도 특정 질문 유형이 나빠지면 원인을 분석한다. 근거 없는 MATCH, 부정·무효 결과 감점, 평가 실패 은폐가 없어야 한다. 소규모 평가이므로 통계적으로 입증된 일반적 개선이라고 주장하지 않는다. 실제 수치를 확인하기 전에는 성공으로 표시하지 않는다.

## 구현 단계로 넘어갈 때 지킬 사항

- `source_score`, `source_rank`, `alignment_score`, `final_rank`를 분리해 저장한다. 원본 점수를 덮어쓰지 않는다.
- 검색 실행별 후보·평가·최종 순위를 연결하고 UI evidence 조회도 같은 실행을 기준으로 한다.
- 기존 겹침 등급과 COUNTER/MOTIVATING/ENABLING 역할을 정합성 점수로 대체하지 않는다. 정합성만으로 신규성이나 가설 지지 여부를 판정하지 않는다.
- 먼저 동일 후보의 재정렬 효과를 검증한다. 알려진 관련 논문이 후보에 없으면 질문 필드에 따른 쿼리 분해·확장과 후보 병합을 별도 실험한다.
- embedding·BM25·hybrid 도입은 후보 누락 유형과 추가 검색원의 필요성을 확인한 후 결정한다.
- 검증 범위: UNKNOWN과 MISMATCH 구분, 미지정 필드 제외, 근거 인용 검증, 결과 방향에 무관한 평가, 동점 순서, 실패 fallback, 같은 gap의 복수 검색 실행, API와 화면 순서 일치.

## 다음 실행 작업

[실제 후보 스냅샷과 수동 평가표](evaluation/research-question-alignment-v0.1/README.md)를 준비했다. 원문 검색은 2개 질문에서 0건, 물음표가 있는 4개 질문에서 HTTP 400을 반환했다. 원문·물음표 제거·키워드 진단 검색을 분리해서 보존했고, 진단 후보 300쌍을 수동 평가 대상으로 삼았다. 이 후보 확보를 reranking 성능 개선으로 해석하지 않는다.

다음은 질문 조건을 검토하고 사람이 평가표를 작성하는 단계다. 이번 문서의 가상 예시를 실제 평가셋이나 완료된 성능 실험으로 대체 표기하지 않는다. 실제 평가를 통해 CORE 우선 정책과 가중치를 조정한 뒤 오프라인 reranking 구현 범위를 확정한다.
