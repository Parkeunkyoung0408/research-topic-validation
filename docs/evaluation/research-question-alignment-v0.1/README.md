# 정합성 검색 평가셋 v0.1

2026-09-09에 OpenAlex 공개 API에서 수집한 탐색용 데이터다. 애플리케이션 코드는 변경하지 않았다. 질문 6개와 조건 지정은 도우미가 제안한 초안이며 사용자 확정 질문이 아니다. 사람 정답 판정과 reranking 성능 평가는 아직 수행하지 않았다.

## 선정 질문과 수집 결과

요청은 기존 어댑터와 같은 `GET https://api.openalex.org/works`, `search`, `per-page=50`, `sort=relevance_score:desc`를 사용했다. 현재 UI의 10건보다 후보 수만 늘렸다. 외부 API를 직접 읽었으며 로컬 앱 DB에는 검색을 생성하지 않았다.

| 질문 | 분할 | 연구 질문 | 원문 검색 | 물음표만 제거 | 키워드 진단 검색 |
|---|---|---|---|---|---|
| Q01 | 조정용 | 생성형 AI가 UX 디자이너의 아이디어 다양성에 미치는 영향 | 200, 0건 | 해당 없음 | 50건 |
| Q02 | 조정용 | How does generative AI affect idea diversity among UX designers? | 400, 요청 거부 | 200, 50건 | 50건 |
| Q03 | 조정용 | How do university students experience using ChatGPT for academic writing? | 400, 요청 거부 | 200, 50건 | 50건 |
| Q04 | 검증용 | 설명 가능한 AI의 설명 방식은 사용자의 신뢰에 어떻게 영향을 미치는가? | 400, 요청 거부 | 200, 0건 | 50건 |
| Q05 | 검증용 | Does retrieval augmented generation reduce hallucinations compared with language models without retrieval? | 400, 요청 거부 | 200, 50건 | 50건 |
| Q06 | 검증용 | 원격 근무가 소프트웨어 개발자의 생산성에 미치는 영향 | 200, 0건 | 해당 없음 | 50건 |

Q01·Q02는 같은 질문의 한영 쌍이므로 모두 조정용이다. 총 6개 질문이지만 독립된 의미 주제는 5개다. 효과 질문뿐 아니라 경험(Q03), 영향 메커니즘(Q04)을 포함한다. 방법과 기간은 원문에 명시되지 않아 모두 미지정이다. 기간·방법 조건 평가에는 별도 질문을 추가해야 한다.

## 이번 수집에서 확인한 문제

원문 검색의 네 요청에서 OpenAlex가 `?`를 와일드카드로 해석하고, 기본 stemmed 검색에서 허용하지 않는다는 HTTP 400 응답을 반환했다. [Q02 원본 오류](raw/Q02-baseline.json)에 응답을 보존했다. 이는 이번 요청에서 관찰한 동작이며 모든 문장부호나 모든 검색 방식에 대한 일반화가 아니다.

물음표만 제거한 Q02·Q03·Q05는 각각 50건을 반환했다. 한국어 Q01·Q06 원문과 Q04 물음표 제거 검색은 성공 응답이지만 0건이었다. 그러므로 현재 원문 파이프라인과 reranking만을 비교할 수 있는 상태가 아니다. 우선 입력 처리와 후보 확보 문제를 분리해야 한다.

후보 확보를 위해 별도 영문 키워드 검색을 수행했다. 이는 원문 검색을 대체한 결과가 아니며, 번역·질문 분해의 품질이 검증됐다는 뜻도 아니다. 예를 들어 Q06 진단 검색 상위에는 소프트웨어 개발자의 원격 근무와 직접 맞지 않아 보이는 제목도 있다. 정합성 판정은 제목·초록을 보고 사람이 수행해야 한다.

## 실험군을 섞지 않는 방법

- `baseline`: 질문 원문 그대로. 원문 검색의 성공·빈 결과·실패를 측정한다.
- `punctuation`: 마지막 `?`만 제거. 원문 대비 입력 처리 영향을 진단한다.
- `diagnostic`: 질문별 영문 키워드 쿼리. 후속 고정 후보 reranking 실험에 사용할 50건이다.

수동 평가표는 **diagnostic 300쌍만** 포함한다. 고유 논문은 246개이며 같은 논문이라도 질문이 다르면 별도 평가다. 초록 없는 질문–논문 쌍은 19개다. 표의 검색 건수는 API 전체 매칭 수가 아닌 저장한 첫 페이지 건수다.

후속 reranking 비교에서는 같은 diagnostic 후보 50개 안에서 외부 순위와 정합성 순위를 비교한다. 이를 현재 앱의 원문 검색보다 reranking만으로 좋아졌다고 표현하면 안 된다. 원문 입력 처리 개선 효과는 별도로 비교한다.

조정용·검증용 질문에 공통 논문 3개가 있다. [중복 목록](cross-split-papers.csv)을 보존했다. 질문 단위 분할은 유지했지만 문헌까지 완전히 독립된 검증셋은 아니다. 검증 결과는 전체 후보 기준과 해당 공통 논문을 양쪽 비교 순위에서 제외한 기준을 함께 보고한다. 검증용 사람 판정은 조정에 사용하지 않는다. 한영 쌍을 포함한 소규모 집계이므로 질문별 결과도 반드시 공개한다.

## 수동 검토 전달과 평가 보존

검토자에게는 `reviewer/`만 전달한다. 원본 응답, 점수·순위, 분할 정보, 정답 매핑은 전달하지 않는다. 논문 링크와 제목은 근거 확인을 위해 유지한다. 순위 블라인드이지 논문 정체를 숨긴 평가는 아니다.

`reviewer/`의 두 CSV는 정답 입력용 빈 템플릿이다. 도우미 판정을 사람 정답으로 채우지 않았다. `known-relevant-papers.csv`도 빈 참조 목록이며, 전문가가 확인한 논문만 추후 추가한다. 따라서 현재 알려진 관련 논문 후보 포함률은 계산할 수 없다.

검토 시작 전 질문 조건과 CORE 지정에 대한 이견을 확인한다. 조건을 수정하면 질문 버전을 올리고 해당 질문의 모든 후보를 같은 버전으로 판정한다. 2차 검토자는 CSV를 별도 복사해 독립 작성하고, 합의본은 원본 판정을 덮어쓰지 않고 별도로 저장한다.

## 재현성과 다음 실행

원본 API 응답은 `raw/`에 있고 `search-runs.json`에 SHA-256을 기록했다. 시각은 응답 파일 저장 완료 직후의 파일 수정 시각(UTC)이며 서버 검색 시작 시각은 아니다. 다시 API를 호출하면 색인과 순위가 바뀔 수 있으므로 같은 실험에서는 이 스냅샷을 사용한다. 외부 응답의 초록 역색인은 위치 순으로 복원했고 누락된 초록은 생성하지 않았다.

다음 순서로 진행한다.

1. 조정용 Q01~Q03의 질문 구조를 검토한다.
2. 조정용 표본으로 판정 규칙을 맞춘 뒤 300쌍 전체를 평가한다. 검증용 답안은 실험 조정 담당자에게 노출하지 않는다.
3. 미판정·정보 부족을 구분해 정답본을 확정한다.
4. 동일 후보에서 정합성 reranking 실험을 구현하고 nDCG@10, 직접 관련 Precision@5, CORE 불일치@5를 비교한다.

이번에 완료한 것은 실제 후보 스냅샷과 수동 평가 준비다. 순위 개선의 실증 결과는 아직 없다.
